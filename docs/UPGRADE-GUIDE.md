# UPGRADE-GUIDE.md — Complior Version Upgrades

**Updated:** 2026-05-04 (post v1.0.1 release)

> **Purpose:** Step-by-step upgrade instructions between Complior versions. Includes breaking-change notes, deprecation timelines, and verification steps.

---

## Quick reference

| From → To | Breaking changes | Action required |
|-----------|------------------|-----------------|
| v1.0.0 → v1.0.1 | None | Standard upgrade |
| v0.9.x → v1.0.x | None (semantic only) | Standard upgrade |
| v0.8.x → v1.0.x | None (semantic only) | Standard upgrade |
| pre-v0.8 → v1.0.x | Multiple | Recommend fresh install |

## Upgrading to v1.0.1 (latest)

**From v1.0.0** — pure patch release. Zero breaking changes.

### Standard upgrade

<details open>
<summary><b>npm</b></summary>

```bash
npm install -g complior@1.0.1
```

</details>

<details>
<summary><b>cargo</b></summary>

```bash
cargo install --force complior-cli
# Forces reinstall over existing v1.0.0 binary
```

</details>

<details>
<summary><b>GitHub Release binary</b></summary>

```bash
# Linux x86_64 example
curl -fsSL -o complior https://github.com/complior/complior/releases/download/v1.0.1/complior-linux-x86_64
chmod +x complior
sudo mv complior /usr/local/bin/

# Verify checksum
curl -fsSL -o checksums.txt https://github.com/complior/complior/releases/download/v1.0.1/checksums.txt
sha256sum -c checksums.txt --ignore-missing
```

Other platforms: replace `linux-x86_64` with `linux-aarch64`, `macos-x86_64`, `macos-arm64`, or `windows-x86_64.exe`.

</details>

### What changed

`complior fix --doc <type>` now surfaces actual engine error messages:

```diff
# Before v1.0.1
$ complior fix --doc fria
Generating 'fria' document for passport 'default'...

Document generated:
  Type:      fria
  Passport:  default
  Saved to: unknown
  Prefilled: 0 field(s)
  Manual:    0 field(s) remaining

# After v1.0.1
$ complior fix --doc fria
Generating 'fria' document for passport 'default'...
Error: Passport not found: default
```

The functional behaviour was already correct in v1.0.0 (exit code 1, no actual document written). Only the displayed message has improved.

### Verification

```bash
complior --version
# complior 1.0.1

complior doctor
# ✓ Engine: OK
# ✓ Node.js: v22+
# ✓ TUI: OK
# ✓ MCP: OK
```

### Rollback

If you need to roll back to v1.0.0 for any reason:

```bash
# npm
npm install -g complior@1.0.0

# cargo
cargo install --force complior-cli@1.0.0

# binary — download from https://github.com/complior/complior/releases/tag/v1.0.0
```

## Upgrading to v1.0.0 (initial GA)

**From v0.9.x or v0.8.x** — semantic version bump, no breaking changes.

### What changed

v1.0.0 is the first general-availability release. It consolidates all features from v0.8 → v0.9 alpha/beta cycles into a stable, production-ready package.

See [CHANGELOG.md](../CHANGELOG.md) for the full release notes.

### Highlights since v0.9.9

- Profile-aware filtering (16/67/46 obligations across role × risk × domain)
- 11 EU AI Act conformity categories + 300 OWASP/MITRE security probes (680 total eval probes)
- Multi-framework scoring (EU AI Act + AIUC-1 + OWASP + MITRE)
- ISO 42001 generators (SoA, Risk Register, AI Policy)
- Adversarial Test Runner (`complior redteam`, 300+ probes)
- 12 mini-hotfix milestones polished pre-tag (V1-M30.1 → V1-M30.11)

### Standard upgrade

Same as v1.0.1 — replace `1.0.1` with `1.0.0` in all install commands.

## Deprecation timeline

| Feature | Deprecated since | Removal version | Notes |
|---------|------------------|-----------------|-------|
| `complior passport <verb>` alias | v1.0.0 (V1-M30.4) | v2.0.0 | Use `complior agent <verb>`. Both work in v1.x. |
| `complior docs --article` | v1.0.0 (V1-M30.9 W-1) | already removed | Use `complior fix --doc <type>` instead. |

### Renaming heads-up

In v1.0.x, the **agent** verb is canonical:
```bash
complior agent init my-agent      # ✅ canonical
complior passport init my-agent   # ⚠️ deprecated alias (works, prints warning)
```

In v2.0.0, only `complior agent` will be supported.

## Configuration file changes

### `.complior/project.toml` (v1.0.x stable schema)

Schema is stable across the v1.0.x line. Files written by v1.0.0 are read correctly by v1.0.1.

If you hand-edit the file: see [`engine/core/src/types/project-toml.types.ts`](../engine/core/src/types/) for the canonical TypeScript schema.

### `~/.config/complior/settings.toml` (global)

Schema stable. New fields are added with defaults, never required.

### `~/.config/complior/keys/` (ed25519 keys)

**No action required.** Keys generated by v1.0.0 work with v1.0.1. Manual key rotation is currently outside automated upgrade flow — see [SECURITY.md](../SECURITY.md#cryptographic-key-management).

### `.complior/.env` (LLM API keys)

Schema stable. New providers may be added with backward-compatible variables.

## Project state migration

For projects scanned with an older Complior version:

1. Re-run `complior init` to refresh `profile.json` with current onboarding question set (V1-M09 added 9 questions; pre-V1-M09 profiles may be missing fields).
2. Re-run `complior scan` — all evidence chain entries from older runs remain valid (chain is append-only).
3. Optional: Re-run `complior agent init --force` to refresh passport with v1.0.x field set (some fields added since v0.8).

No data is destroyed by the upgrade. Old `.complior/` directories are forward-compatible with v1.0.x.

## Version pinning recommendations

### CI / CD

Pin to exact version for reproducibility:

```yaml
# GitHub Actions
- name: Install Complior
  run: npm install -g complior@1.0.1

- name: Compliance gate
  run: complior scan --ci --threshold 70 --fail-on high
```

### Production daemon

Pin to minor version, allow patches:

```bash
npm install -g complior@1.0
# This installs the latest 1.0.x — currently 1.0.1
```

### Development

Latest is fine:

```bash
npm install -g complior@latest
```

## Verification checklist after upgrade

- [ ] `complior --version` reports the new version
- [ ] `complior doctor` shows all green checks
- [ ] `complior scan` produces a score (no errors about missing fields/files)
- [ ] `complior agent show <name>` displays existing passport correctly
- [ ] Existing CI script runs without changes (no breaking flags)

If any of these fail after upgrade, please [open an issue](https://github.com/complior/complior/issues).
