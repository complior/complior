## Background

Final /deep-e2e on `dev` (post V1-M30.10 with W-3 root cause closed) revealed:
- W-1, W-2, W-3 fixes ALL confirmed clean ✅
- BUT 2 P2/P3 UX bugs surfaced

**BUG-1 (P2 — UX/error-handling)**: `complior fix --doc <type>` swallows engine errors silently.

42 occurrences across 3 profiles × 14 doc types showed:
```
Document generated:
  Type:      fria
  Passport:  default
  Saved to: unknown          ← misleading
  Prefilled: 0 field(s)      ← misleading
  Manual:    0 field(s) remaining   ← misleading
```

Live curl proved the engine returned a 400 error:
```json
{"error":"VALIDATION_ERROR","message":"Passport not found: default"}
```

`engine_client::post_json` deliberately returns `Ok(error_json)` for non-2xx status when the body is parseable JSON (so callers can read structured error fields). But the doc-generate handlers (`run_doc_generate_single` in `fix.rs:1396` and `doc.rs:155-180,209-280`) DON'T check for the `error` field — they just call `result.get("savedPath")` which returns None → fallback "unknown".

User sees fake "Document generated" message when the real outcome is "Passport not found".

**BUG-3 (P3 — UX)**: `complior scan --diff main` on non-git project dumps full git `--help` text.

`cli/src/headless/scan.rs:676-679` does:
```rust
eprintln!("Warning: git diff failed: {}", String::from_utf8_lossy(&o.stderr).trim());
```

When the project is not a git repo, git's stderr contains the full `git diff --help` output (~70 lines). Should print short friendly message instead.

**BUG-2 (P3 — UX)**: `Prefilled: 0 / Manual: 0` for FRIA in fix --doc output.
This is a **symptom of BUG-1**: when engine returns error JSON, neither `prefilledFields` nor `manualFields` are present. Fixing BUG-1 fixes BUG-2 automatically.

## Architecture Requirements

- ✅ Use existing `result.get("error")` and `result.get("message")` JSON paths — no new types
- ✅ Bail with non-zero exit code when engine returned error
- ✅ Print error to stderr (not stdout) so `--json` consumers aren't polluted
- ✅ Keep `--json` mode behavior intact: print raw JSON regardless (let consumer parse error)
- ✅ For `scan --diff` git failure: detect "not a git repository" (case-insensitive) → print 1-line friendly message; OR truncate stderr to first 200 chars
- ❌ NO `--no-pager` hack on git, NO retry loops, NO new dependencies
