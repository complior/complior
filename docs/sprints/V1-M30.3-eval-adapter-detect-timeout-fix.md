## 1. Goal — kill the auto-detect race condition

`/deep-e2e` Profile B's eval `--full` returned **all 635 tests as `verdict: error`** with reasoning `Error: AdapterError: API error 404: non-JSON response`. Profiles A and C succeeded with real scores (87 / 88, grade B). Reproduced cold.

### Root cause (verified)

`engine/core/src/domain/eval/adapters/auto-detect.ts` step 4.5 `tryOpenAIPost`:

```ts
const tryOpenAIPost = async (
  baseUrl: string,
  model?: string,
  key?: string,
  timeout = 3000,    // ← 3 seconds for a real LLM round-trip
): Promise<boolean> => {
  // ...
  const res = await fetch(`${baseUrl}/v1/chat/completions`, {
    method: 'POST',
    body: JSON.stringify({
      model: model ?? 'gpt-4o',
      messages: [{ role: 'user', content: 'ping' }],
      max_tokens: 5,
    }),
    signal,
  });
  return res.ok;
};
```

It POSTs a real chat completion to detect OpenAI-compat endpoints. The probe goes through the local AI server which proxies to OpenRouter (real LLM inference). When the LLM is cold or under load, the round-trip exceeds 3s → timeout → `tryOpenAIPost` returns `false` → auto-detect falls back to the **generic HTTP adapter** (line 147).

The generic HTTP adapter POSTs `{message: probe}` to the **root path** of the URL. Our AI server doesn't expose `POST /` — it 404s with HTML. → `AdapterError 404: non-JSON response` → all tests get this error verdict.

### Race condition table (cold reproduction)

| Profile | Adapter chosen | overallScore | verdict counts |
|---|---|---|---|
| A | openai (probe < 3s) | 87 (B) | 541 pass / 46 fail / 32 err |
| **B** | **http (probe ≥ 3s, fallback)** | **0 (F)** | **0 / 0 / 635** |
| C | openai (probe < 3s) | 88 (B) | 565 pass / 39 fail / 25 err |

**Fix verified:** explicit URL `http://127.0.0.1:4000/v1/chat/completions` makes auto-detect match the path heuristic at line 135 → directly chooses OpenAI adapter, no LLM probe → Profile B with same project context yields **adapterName=openai, overall=92 (A), 136 pass / 10 fail / 0 err**.

## 2. Two-part fix

### Part A — `scripts/verify_truly_deep_e2e.sh` (architect, 1 line) — DONE in this commit

Already applied:

```bash
# Before
AI_TARGET="${AI_TARGET:-http://127.0.0.1:4000}"

# After
AI_BASE="${AI_BASE:-http://127.0.0.1:4000}"
AI_TARGET="${AI_TARGET:-${AI_BASE}/v1/chat/completions}"
```

`/health` probes use `AI_BASE`; eval target uses `AI_TARGET`. This makes `/deep-e2e` deterministic for our test pipeline. Does NOT fix the underlying engine bug for end users.

## 3. Architecture Requirements (mandatory for nodejs-dev)

- `tryOpenAIPost` default timeout MUST be `15000` (declared as a named const, not a magic number)
- Auto-detect logger emission MUST be optional (passed via `AutoDetectOptions.logger?: { warn(msg: string): void }`) — NO global logger import
- Backward compatibility: existing callers without logger continue to work
- DO NOT change adapter selection priority order (still: hint → /v1/models → /api/tags → URL contains /v1/chat → tryOpenAIPost → http fallback)
- DO NOT break any existing test in `engine/core/src/domain/eval/adapters/`
- All factories return `Object.freeze(...)`
- Pure functions stay pure
- DO NOT touch Rust CLI
