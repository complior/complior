## 2. Issues

### Issue 1 (REAL bug, A.4 file:// links broken on ALL 3 profiles)
**Root cause:** `engine/core/src/domain/reporter/html-renderer.ts` lines 885 & 922:
```ts
? (d.outputFile.startsWith('/') ? d.outputFile : `${process.cwd()}/${d.outputFile}`)
```
`process.cwd()` returns the engine's working directory (`engine/core/`), not the
user's project. All 13-14 file:// links per profile point to non-existent paths.

**Fix:** thread `report.summary` (or report root) so the renderer can read the
**actual scanned project path**, which is already on `scanResult.projectPath`.
Add a new optional field `projectPath: string | null` on `ComplianceReport.summary`
populated by `report-builder.ts` from `scanResult.projectPath`.
The renderer uses `report.summary.projectPath ?? process.cwd()` as fallback.

### Issue 2 (REAL bug, A.6 Actions emoji incomplete)
**Root cause:** `renderTabActions` in `html-renderer.ts` does TWO things that drop actions:
1. Line 1179 filters out any `command =~ /passport\s+init/` (legacy V1-M11 cleanup that
   over-fires post V1-M30.4 rename).
2. Line 1190-1194 deduplicates by `a.command`, collapsing distinct actions (e.g. two
   obligations both with `command: "manual review"` → only one rendered).

After both filters, Profile A: 5 actions → 2 rendered. Each gets one emoji, so the
output looks like only 2 sources have icons. Reality: 3 actions never make it to
the rendered list at all.

**Fix:**
- Replace command-based dedup with `id`-based dedup (each action has a unique `id`
  via `${source}:${title}` or similar). If `id` exactly duplicates, dedup; otherwise
  keep both rows so each gets its emoji + Done state.
- Update the legacy filter regex to be inclusive of both `passport init` AND
  `agent init`, AND only fire when the command is EXACTLY one of these (not
  substring match) — so legitimate passport-source actions with different commands
  (e.g. `complior agent show <name>`) survive. Or: REMOVE the filter entirely
  (V1-M11 was 5+ months ago; the action plan doesn't generate `passport init` actions
  any more — verified in production data).

### Issue 3 (Minor, MD report timestamp not humanized)
**Root cause:** `engine/core/src/domain/reporter/md-renderer.ts` (or wherever MD is
rendered) uses raw `report.generatedAt` ISO string in the header.

**Fix:** Import `formatDateTimeHuman` from `format-dates.ts` and use it for the
"Generated by Complior on …" line.

### Issue 4 (Minor, passport list stdout still says "complior passport init")
**Root cause:** Rust CLI prints "Run `complior passport init` to generate one." in
`cli/src/headless/passport.rs` (or similar) when the list is empty.

**Fix:** change the hint to `complior agent init`. The CLI command itself is now
the agent variant (passport is alias), so the hint should reflect the new primary.

## 3. Architecture Requirements (mandatory)

### Engine (Issue 1 + 2 + 3)
- `ComplianceReport.summary.projectPath?: string | null` — new optional field on
  the existing summary type. No breaking change.
- `report-builder.ts` populates it from `scanResult.projectPath` (already exists in
  data per `last-scan.json` inspection).
- `renderTabDocuments` reads `report.summary.projectPath ?? null`; passes through a
  helper `resolveDocumentPath(outputFile, projectPath)` that:
  - returns absolute `outputFile` if it starts with `/`
  - returns `${projectPath}/${outputFile}` if `projectPath` set
  - falls back to `${process.cwd()}/${outputFile}` (last resort, with a comment that
    this is a degraded path)
- `resolveDocumentPath` is a **pure function**, exported with JSDoc, named export, in
  `html-renderer.ts` (or new file `path-helpers.ts` if you prefer)
- `renderTabActions` dedup logic switches from `command` to `id` (or removes dedup
  entirely if all actions are unique-by-design)
- `renderTabActions` legacy filter: change to exact-match list `['complior passport init', 'complior agent init']` AND/OR remove the filter — choose whichever the production data audit allows
- `md-renderer.ts` (or wherever MD format is rendered) imports `formatDateTimeHuman`
  and applies it to the timestamp line
- All RED tests committed in this branch must remain unchanged

### Rust CLI (Issue 4)
- One-line change in `cli/src/headless/passport.rs` (or wherever the empty-list hint
  is printed): `complior passport init` → `complior agent init`
- All existing 214+ Rust tests must continue to pass
- `cargo fmt` + `cargo clippy --all-targets -- -D warnings` clean
