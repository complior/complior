## Background

V1-M30.9 W-3 spec said: "predicted score after fix must be capped at 99, not 100".
Two production code paths compute `predictedScore`:

1. **Rust offline fallback** — `cli/src/headless/fix.rs:119` (when engine call fails).
   ✅ Already capped at `99.0` in V1-M30.9 commit `e995f96`.

2. **Rust connected branch** — `cli/src/engine_client.rs:201` (`fix_dry_run` engine call).
   ❌ Still capped at **`100.0`** — V1-M30.9 missed this site.

**Evidence** from final /deep-e2e (post V1-M30.9 merge, on `dev`):

```
═══ V1-M30.9 W-3: fix score estimate <99 (not hardcoded 100)? ═══
  Profile A fix_dry.log: 67 → ~100   ❌ FAIL
  Profile B fix_dry.log: 70 → ~100   ❌ FAIL
  Profile C fix_dry.log: 71 → ~100   ❌ FAIL
```

`fix_dry.log` JSON output:
```json
{"changes": [...], "predictedScore": 100.0, "totalImpact": 35.0}
```

The `100.0` comes from `engine_client.rs:201`:

```rust
let predicted = (current_score + adjusted_impact).clamp(current_score, 100.0);
//                                                                       ^^^^^
//                                                                BUG — must be 99.0
```

Calling chain:
```
complior fix --dry-run
   ↓
cli/src/headless/fix.rs:102  →  client.fix_dry_run(current_score)
                                       ↓
cli/src/engine_client.rs:154 →  fix_dry_run() — calls GET /fix/preview
                                       ↓
cli/src/engine_client.rs:201 →  .clamp(current_score, 100.0)   ← ROOT CAUSE
                                       ↓
                                returns JSON {"predictedScore": 100.0}
                                       ↓
cli/src/headless/fix.rs:111  →  format_dry_run_report() — prints "100"
```

The OFFLINE branch (fix.rs:119, my V1-M30.9 patch) only fires if the engine call **fails**. In a healthy daemon it never fires, so the V1-M30.9 patch was a dead-code patch from the user's perspective.
