## Background

V1-M30.11 fixed BUG-1 (fake "Document generated" + "Saved to: unknown" when engine returns 4xx) but rust-dev's implementation read the error message from the WRONG JSON path.

Engine returns flat shape:
```json
{"error": "VALIDATION_ERROR", "message": "Passport not found: default"}
```

rust-dev's V1-M30.11 code (3 sites in `fix.rs` + `doc.rs`):
```rust
// WRONG
if let Some(err_obj) = result.get("error") {
    let msg = err_obj
        .get("message")  // ← error is a STRING, not object
        .and_then(|v| v.as_str())
        .unwrap_or("Unknown engine error");
    eprintln!("Error: {msg}");
    return 1;
}
```

`result.get("error")` returns the string `"VALIDATION_ERROR"`. `.get("message")` on a string returns `None`. Falls back to generic `"Unknown engine error"`.

**Result for users**:
- Before V1-M30.11: fake `Document generated` + `Saved to: unknown` (worse — silent corruption)
- After V1-M30.11: `Error: Unknown engine error` (better — clear failure but unhelpful)
- After V1-M30.12: `Error: Passport not found: default` (correct — actionable message)

## Architecture Requirements

- ✅ Read `message` from TOP-LEVEL of result (not nested inside error)
- ✅ Fall back to `error` code if message is absent (not the literal string "Unknown engine error")
- ✅ Apply identical pattern in all 3 sites
- ✅ Print to stderr, return exit code 1
- ❌ NO type changes, NO new helper functions, NO API changes

---

## Correct pattern

```rust
if let Some(err) = result.get("error").and_then(|v| v.as_str()) {
    let msg = result
        .get("message")
        .and_then(|v| v.as_str())
        .unwrap_or(err);  // fallback to error code (e.g. "VALIDATION_ERROR") if no message
    eprintln!("Error: {msg}");
    return 1;
}
```

Three sites must be updated identically.
