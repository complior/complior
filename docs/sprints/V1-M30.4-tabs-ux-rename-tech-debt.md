## 2. Section A — Tab UX Polish (nodejs-dev)

### A.1 Tab intros — short explainer per tab (HR-T_INTRO)

Every tab should open with a **2-3 sentence `<p class="tab-intro">`** explaining:
- WHAT this tab shows
- WHY it matters
- HOW to read it

Required intros (HTML rendering):

| Tab | Intro text |
|---|---|
| Overview | "Your overall EU AI Act readiness across 7 dimensions. Green ≥ 80, yellow 60-79, orange 40-59, red < 40. Each dimension has equal weight (1/7) — they all matter for compliance certification." |
| Tests | "Test results from your AI system: rule-based scan checks (`complior scan`), deterministic eval probes (`complior eval --det`), AI-judged disclosure tests (`complior eval --llm`), and OWASP LLM Top 10 security probes (`complior eval --security`)." |
| Findings | "Issues found by the 5-layer scanner in your code, configs, and documents. Each card shows what was found, why it matters under EU AI Act, and what to do. Apply fixes via `complior fix --check-id <id>` then re-scan to verify." |
| Laws | "EU AI Act regulatory obligations applicable to your profile (role × risk level × domain). 'Covered' means you have an artifact (scan finding, document, or passport field) demonstrating compliance. 'Pending' means action needed." |
| Documents | "Required compliance documents per EU AI Act. **Missing**: file doesn't exist. **Scaffold**: placeholder template. **Draft**: partially filled. **Reviewed**: finalised. Click any document to open it in your editor." |
| Fixes | "History of `complior fix` applications. **Score change** shows the impact on overall readiness — small numbers are normal because score averages 7 dimensions. Each fix improves ONE dimension; aggregate impact accumulates over time." |
| Passports | "Agent Passports — identity documents for each AI system in your project. Required by EU AI Act Art. 11+ for transparency. Completeness % = filled fields / 36 total. Run `complior agent show <name>` to view missing fields." (NOTE: command name reflects rename in Section B) |
| Actions | "Prioritised next steps to improve compliance. Ranked by severity, deadline urgency, and predicted score impact. Click the command on any action to copy it to clipboard." |
| Timeline | "EU AI Act enforcement deadlines. **August 2, 2025** — AI literacy. **August 2, 2026** — main enforcement (most obligations). **August 2, 2027** — Annex III high-risk systems. Past deadlines are highlighted in red." |

### A.2 Findings — re-scan hint when fix applied (HR-FIND-1)

For each `finding-card` rendered, check if `fixHistory[*].checkId === finding.checkId`. If yes:
- Add a small badge after the title: `<span class="tag tag-amber">Fix applied — re-scan to verify</span>`
- Render at the top of card section a small banner: `<p class="muted small">N findings have applied fixes. Run <code>complior scan</code> to update this view.</p>`

### A.3 Laws — per-obligation status + linked-check links (HR-LAWS-1)

Per obligation row in Laws tab:
- Status badge: ✅ Covered / ⏳ Pending / 🚨 Past-due / ⚠️ Critical (use existing `o.covered` + `o.deadline` + severity)
- "Linked checks" section: for each `linkedCheck` in `o.linkedChecks`, render a clickable anchor `<a href="#tab-findings" class="tab-link" data-tab="findings">→ {checkId}</a>` (existing tabs.js handles tab switching if present; otherwise just visible text)
- Group obligations by status (Pending / Covered / Past-due / Future) under each article

### A.4 Documents — clickable file links + inline preview (HR-DOC-1)

Each document card:
- Title becomes `<a href="file://${absolute_outputFile}" target="_blank">${docType}</a>` — click opens in editor (browsers respect file:// for local HTML reports)
- If `documentContents` array contains `{docType, content}` for this doc, render `<details><summary>Preview</summary><div class="doc-preview">${markdownToHtml(content)}</div></details>` after the meta line
- Status legend at top of tab: `<div class="legend">Missing: not created. Scaffold: placeholder template. Draft: partial. Reviewed: finalised.</div>`

### A.5 Fixes — per-fix dimension change explanation (HR-FIX-1)

Above the fixHistory table, add an explainer:
> "Score change shows the **overall readiness delta** (averaged across 7 dimensions). Small numbers are expected — each fix typically improves one dimension by 5-10 points, which becomes ~1 point in the overall average. Cumulative effect is what matters."

Per-row in fixHistory: if `scoreBefore === scoreAfter`, show in muted text "no overall change (single-dimension improvement)" instead of bare `77 → 77`.

### A.6 Actions — source icons + click-to-copy command (HR-ACT-1)

Each action row:
- Prefix title with source icon:
  - `obligation` → 📋
  - `scan` → 🔍
  - `document` → 📄
  - `passport` → 🤖
  - `eval` → 🧪
- The `command` field rendered as `<code class="copy-cmd" data-cmd="${escape(cmd)}">${cmd}</code>` (existing JS may handle copy-on-click; otherwise just visible)
- If `actionPlan.actions[*].id` matches any `fixHistory[*].checkId`, prepend `<span class="tag tag-green">✓ Done</span>` and dim the row

### A.7 Tests — failed-first sort within each section (HR-TESTS-1)

In `renderTestSection`, sort `tests` array by:
1. verdict (error/fail first, then pass)
2. severity (critical → low)
3. confidence (high first)

Currently rendering uses input order. Switch to a sorted copy (don't mutate input).

## 3. Section B — CLI Rename `passport` → `agent` (rust-dev + nodejs-dev)

### B.1 Decision

`agent` becomes the PRIMARY CLI command. `passport` kept as **deprecated alias** that:
- Continues to work
- Prints a one-line yellow warning: `⚠ Deprecated: 'complior passport' is now 'complior agent'. The 'passport' alias will be removed in v2.0.0.`

Internal types (`AgentPassport`, `AgentPassportSchema`, `loadOrCreateKeyPair`) **remain unchanged** — they correctly model the document concept.

### B.2 Rust CLI changes

Files:
- `cli/src/cli.rs` — add `Agent { ... }` enum variant (mirror existing `Passport`); change `Passport` description to mention deprecation
- `cli/src/headless/passport.rs` → rename to `cli/src/headless/agent.rs` (or keep file, rename functions). Add `print_deprecation_warning()` helper called at the start of `run_passport_command` if invoked
- `cli/src/main.rs` — dispatch `Agent` to same handler; dispatch `Passport` to handler with deprecation flag
- All RUST tests in `cli/src/headless/tests.rs` covering `passport` continue to work; add ONE new test `agent_command_works_same_as_passport`

### B.3 Engine HTTP routes

- `engine/core/src/http/routes/passport.route.ts` — keep all existing `/passport/*` routes (no break); ADD `/agent/*` routes that proxy to the same handlers
- Both URLs return identical responses

### B.4 Documentation

- `CLAUDE.md` v1.0.0 scope table — change `complior passport` → `complior agent` (add note: "alias `complior passport` deprecated")
- `docs/PRODUCT-VISION.md`, `docs/STRATEGY.md`, `docs/TUI-DESIGN-SPEC.md` — update references

### B.5 Tab in HTML report

In `renderTabPassports` and `renderTabActions`, change command examples from `complior passport ...` → `complior agent ...`

## 4. Section C — Tech Debt (architect)

### C.1 TD-57 — Timeline analyzer regex (humanized dates compat)

`scripts/verify_truly_deep_e2e.sh` Timeline detector currently checks:
```py
has_2026 = '2026-08-02' in tab or 'August 2026' in tab
```

After V1-M30.2, HTML now contains `August 2, 2026` (with comma). Update regex to also accept the humanized form:
```py
has_2026 = '2026-08-02' in tab or 'August 2, 2026' in tab or 'August 2026' in tab
```

Same for `2027-08-02` → `August 2, 2027`. Verified previously.

### C.2 TD-58 — Findings analyzer counts data, not rendered cards

Current detector:
```py
counts[p] = n_data  # data-level finding count, same across all profiles
```

Should be:
```py
counts[p] = html.count('<div class="finding-card">')  # rendered card count
```

Profile A renders 20 cards, B/C render 24 — counts genuinely differ across profiles.

### C.3 TD-59 — ed25519/HMAC unification (DEFER to v1.0.1)

Out of scope for V1-M30.4. Tracked as separate item:
- `init-service.runInit()` uses HMAC for genesis signing
- `composition-root.ts` uses ed25519 for chain entries
- V1-M30.1 mitigated this via lenient verify(), but root cause persists
- Fix: unify both call sites on `loadOrCreateKeyPair()` from composition-root

This is internal architecture, no user-facing impact, doesn't block v1.0.0.
