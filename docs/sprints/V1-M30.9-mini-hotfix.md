### W-1 (architect, mechanical Rust patches — DONE in working tree)

V1-M30.8a W-3 spec said "Replace `complior docs generate --missing` (and any
other `complior docs ...` literal)" but the RED test only scanned TS engine.

- `cli/src/headless/format/human.rs:642` `dim(&format!("complior docs --article {art_num}"))` → REMOVED entirely (the `complior fix --check-id` hint above is the correct actionable next step; the docs hint was redundant + invalid)

Architect already applied (in working tree, on this branch). Mechanical text
substitution = exception per the same Option-3 grant for V1-M30.8a W-1.

### W-2 (nodejs-dev): Fix CREATE/ENRICH detection broken

V1-M30.8a W-7 spec required: "Existing files → action.type = enrich/edit, not create."
Real `/deep-e2e` output verifies this is NOT working — every fix dry-run shows
`FILES TO CREATE` with files that already exist as `draft` status:

```
FILES TO CREATE  (5 files)
  [PREVIEW]  docs/compliance/ai-literacy-policy.md   ← exists as draft
  [PREVIEW]  docs/compliance/incident-report.md      ← exists as draft
  [PREVIEW]  docs/compliance/risk-management-system.md  ← exists as draft
  [PREVIEW]  docs/compliance/data-governance.md      ← exists as draft
  [PREVIEW]  docs/compliance/instructions-for-use.md  ← exists as draft
```

Documents tab data shows all docs as `draft` status (existing on disk). Plan
must check `existsSync(outputFile)` and emit `enrich` action type.

### W-3 (rust-dev): Fix score estimate hardcoded ~100

V1-M30.8a W-8 spec required: "Compute realistic estimate based on fix priorities
× per-fix score impact." V1-M30.8a Rust test passed (no literal `→ ~100`) but
real CLI output across all 3 profiles still shows:

```
Profile A: SCORE (estimated) 67 → ~100
Profile B: SCORE (estimated) 70 → ~100
Profile C: SCORE (estimated) 71 → ~100
```

The bug is in the `after` value computation, not the format string. After must
be computed as `min(99, before + sum(fix.scoreImpact))`, NOT a hardcoded ceiling.
